# 鹈鹕骑自行车 SVG 2D 动画：设计方案

## 设计依据与阶段边界

依据已完成的 [需求分析](./requirement.md)，交付一个 HTML 页面，以 SVG 绘制鹈鹕骑自行车的连续二维动画。仓库目前只有 README 和需求文档，没有需要沿用的前端工程、业务接口或测试配置。

本阶段仅新增设计文档，确定文件、视觉和动画方案及测试计划。本文中的布局、坐标和周期是后续开发的设计参数，不代表已实现或测试通过。

## 总体方案

采用根目录单文件 `index.html`，包含 HTML 结构、内联 CSS、内联 SVG 和少量原生 JavaScript。用户可以直接打开文件，也可以通过静态 HTTP 服务访问；不依赖构建、第三方库、外部图片、网络字体或 CDN。

SVG 负责绘制角色、车辆和场景。JavaScript 使用一个 `requestAnimationFrame` 循环驱动所有骑行部件，使车轮、踏板、双脚和路面共享时间基准。页面打开后自动播放；系统启用减少动态效果偏好时，默认展示静态骑行姿态，允许用户主动播放。

角色与车辆在画面中保持位置，循环移动路面短线表现前进。此方式能够持续展示完整主体，并让观众同时看清嘴部、车轮与踩踏动作。

## 页面与视觉设计

### 页面布局

- 以插画为视觉主体，使用浅暖色页面背景与居中的展示区域，避免大量说明文字占据画面。
- 使用简短中文标题，例如“鹈鹕的海边骑行”，配一行辅助描述；内容区域只保留一个播放／暂停按钮。
- 展示区域宽度随容器缩放，桌面最大宽度约 1000 CSS 像素；移动端允许标题和控制区换行。
- SVG 使用 `viewBox="0 0 1000 700"`、`preserveAspectRatio="xMidYMid meet"` 和等比宽度缩放，不固定较小视口的高度，不使用会裁切主体的填充缩放方式。
- 头部、长嘴、两只车轮和路面四周保留空白。车辆与鹈鹕占主要视觉面积，装饰物不遮挡角色。

### 插画风格

使用轮廓清楚的二维卡通插画：深蓝灰描边，圆润的线端与连接处；鹈鹕采用暖白身体、浅灰羽翼、橙黄色长嘴与饱满喉囊，搭配可辨识的眼睛、颈部和蹼足。自行车使用青绿色车架、深色轮胎、细辐条和棕色座垫。

背景采用浅蓝天空、简化海面和浅沙色路面，可加入静态云朵与少量植物。车轮转动和路面移动提供主要动态；不增加持续闪烁或大幅镜头运动。

## SVG 图层与元素组织

各组使用稳定且含义明确的 `id`，动画初始化时获取元素引用。图层由后到前组织如下：

1. 背景：天空、海面、云朵和地面。
2. 路面动线与固定投影：动线在完整场景内绘制；阴影不与脚部混淆。
3. 自行车车轮：固定外胎、轮毂，独立旋转的辐条组。
4. 远侧曲柄、踏板、腿和脚：色彩稍暗，体现前后关系。
5. 车架、链条示意、座垫、前叉与车把。
6. 鹈鹕尾部、身体、脖子、头、长嘴与喉囊。
7. 近侧曲柄、踏板、腿和脚，以及伸向车把的羽翼。

通过分组安排遮挡关系，避免前后腿重叠后无法分辨。羽翼末端与车把形成视觉接触，身体位于座垫上方。主体不做整体上下抖动，减少手部和座垫连接点脱离的风险。

初始 SVG 中即写入完整、合理的静态姿态；脚部、腿部和曲柄的初始位置与动画零时刻一致。脚本加载前或停止动画后，图形仍可独立展示。

## 动画数据与关键流程

### 内部数据

不新增对外接口或数据格式。脚本内部保存以下少量状态：

| 类别 | 数据 | 说明 |
| --- | --- | --- |
| 几何参数 | 前后轮中心、车轮半径、曲柄中心与半径、髋部、腿段长度 | 统一使用 SVG 用户坐标。 |
| 时间参数 | 踩踏周期、车轮传动比、路面重复间距 | 初始踩踏周期设为约 2.4 秒，车轮每踩踏周期转 2 圈。 |
| 播放状态 | 是否主动播放、是否页面可见、减少动态偏好 | 控制是否调度动画，不写入本地存储。 |
| 时间状态 | 已播放时间、上一帧时间戳、当前帧请求标识 | 暂停不累计时间，继续沿用当前姿态。 |
| 元素引用 | 两组辐条、曲柄、踏板、腿路径、脚部和路面动线 | 初始化时缓存，避免每帧查找 DOM。 |

### 共享动画相位

令踩踏周期为 `T`，已播放时间为 `t`，曲柄角为 `θ = 2π × (t mod T) / T`。

- 近侧踏板中心：`C + r × (cos θ, sin θ)`。
- 远侧踏板中心：`C + r × (cos(θ + π), sin(θ + π))`，与近侧保持半圈相位差。
- 曲柄端点、踏板和脚部位置使用同一个计算结果，脚底保持与踏板接触；踏板与脚掌保持近似水平，不跟随曲柄倒置。
- 双轮辐条旋转角取 `2θ`，方向与朝右骑行一致；轮胎轮廓固定，不因旋转产生中心漂移。
- 路面以轮缘线速度 `v = 2 × 2π × R / T` 向左移动。使用周期性短线的偏移量，对重复间距取模，使接缝前后视觉一致。

车轮和路面周期对齐，避免明显的倒转或滑行感。每帧只更新少量 SVG 的 `transform`、路径 `d` 与动线偏移属性；不重建 SVG 或页面结构。

### 腿部随踏板变化

以髋部 `H` 为起点、踏板中心 `P` 为脚部终点，使用两段腿构造膝部 `K`，建议腿段长度均约 `85` 个 SVG 单位。

设 `d = |P − H|`、`u = (P − H) / d`，并令 `n` 为朝向选定膝部弯曲侧的单位垂线。膝部距离沿髋部到踏板方向的投影为：

`a = (L1² − L2² + d²) / (2d)`。

垂直偏移为 `h = √max(0, L1² − a²)`，得到 `K = H + a × u + h × n`。绘制从 `H` 经 `K` 到 `P` 的腿部路径，近侧和远侧维持各自固定的弯曲方向。

实现时保护极小距离和平方根输入，并将距离约束在可达范围内。上述建议坐标的髋部到踏板距离约在 96–152 之间，小于两腿段总长 170，因此正常动画无需依靠距离截断。若调整构图，应重新检查整个周期的可达性，确保脚部实际端点始终落在踏板上。

### 初始化与播放流程

1. 浏览器先展示 HTML 与静态 SVG。
2. 脚本获取 SVG 引用，读取 `prefers-reduced-motion`，渲染统一的初始姿态，然后启用控制按钮。
3. 普通偏好下开始动画；减少动态偏好下保持静态，按钮显示“播放动画”。
4. 每帧使用时间戳计算经过时间，更新共享相位，再更新车轮、曲柄、踏板、腿部、脚和路面。
5. 用户暂停时取消后续帧请求并保留当前姿态；继续时重置上一帧时间戳，接续累计播放时间。
6. 页面进入后台时停止帧循环，返回可见状态后仅在用户仍选择播放时恢复；不累计后台时间，避免返回时突然跳动。
7. 动态偏好切换为减少动态时暂停；之后允许用户主动播放。偏好恢复时维持当前播放选择，不擅自重新开始。

只允许一个帧循环存在，重复点击或可见性变化不得叠加循环。每帧时间增量设置合理上限（例如 64 毫秒），降低长任务后动作大幅跳变的影响。

## 易用性与兼容性

- 页面声明中文语言和 UTF-8，设置移动端 viewport。
- SVG 设置 `role="img"`，通过 `title` 和 `desc` 提供“鹈鹕在海边骑自行车”的文字描述；描述涵盖动态与静态状态。
- 使用原生 `button` 提供“暂停动画”／“播放动画”，可通过 Tab 聚焦及 Enter、空格操作，有清楚的键盘焦点样式。
- 按钮文案同步播放选择，页面后台暂停属于内部调度，不改变用户选择。无需高频更新无障碍提示。
- 使用系统字体，页面文字与控件保持可读对比度；视觉主体依靠轮廓和形状识别。
- JavaScript 禁用时仍显示完整静态插画，控制按钮默认隐藏，脚本初始化成功后再显示。
- 目标验证环境为平台浏览器提供的 Chromium；桌面与移动视口均进行验证。使用标准 SVG、原生 DOM 和动画 API，其他现代浏览器暂不宣称已测试支持。

## 风险与替代方案

| 风险 | 处理方式 | 替代方案与取舍 |
| --- | --- | --- |
| 鹈鹕被误认为普通鸟 | 强化长嘴、明显喉囊、长颈与蹼足；静态先确保辨识度。 | 简化羽毛细节，保留关键外形，降低小屏视觉噪声。 |
| 脚离开踏板或腿部突然翻转 | 使用共享踏板坐标和固定膝部弯曲分支；构图调整后检查可达距离。 | 调整髋部、曲柄半径或腿段长度，不通过隐藏双脚规避问题。 |
| SVG 旋转中心在不同缩放下偏移 | 用 SVG `transform` 显式指定旋转中心，保持所有动画在用户坐标中计算。 | 用嵌套 `g` 先平移至轮心再旋转，避免依赖 CSS 百分比原点。 |
| 路面循环出现接缝跳变 | 使用等距、同形短线与相同重复间距，位移按间距取模。 | 如装饰过多，减少动线数量，保留轮转和踩踏这一核心动画。 |
| 暂停或后台返回时动作跳变 | 保留已播放时间，恢复时重置帧时间戳，确保只有一个循环。 | 维持当前静态姿态并等待下一次播放，不重置到零时刻。 |
| 小屏裁切或内容挤压 | SVG 等比缩放，留足安全边距，控制区允许换行。 | 调整外层排版与留白，不裁切主体或改变各部件坐标比例。 |

纯 CSS 或 SVG SMIL 可以更少代码实现简单旋转，但难以同时控制腿部路径、踏板接触和暂停状态；本方案选择统一的原生 JavaScript 动画循环。第三方动画库对这一场景没有必要，不纳入方案。

## 设计结论

方案确定为单文件 HTML、内联 SVG 与统一动画时钟，采用海边二维卡通构图、可协调的双脚踩踏与车轮运动，并提供暂停及减少动态支持。实现范围为新增 `index.html` 与更新 README；验收对应已有 AC-01 至 AC-07。当前没有需要用户补充信息才能推进的设计阻塞项，后续按本方案进入开发。
